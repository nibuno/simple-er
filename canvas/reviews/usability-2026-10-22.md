# SimpleCanvas 使用感レビュー — 2026-10-22

stack #16（nibuno/simple-er#9〜#24）をすべて入れた `canvas/14-dark-mode` を、初めて使う人の目線で通しで操作した。**一番の問題は個々の機能ではなく、「メモ」という言葉と、見ただけでは用途が分からない部品（○の接続点、整頓、ダブルクリックで出るフォーム）にある。** 機能はそろってきたので、言葉と見た目で「何ができるか」を伝える段階に来ている。

これはエージェント1体による操作レビューで、実際のユーザーテストではない。ユーザーの指摘（接続点の○、ダブルクリックで出る「メモ」）を出発点にして、同じ種類の問題を探した。

## 実施条件

- 対象：`canvas/14-dark-mode`（8a2e425 以降の stack 全体）の開発サーバー（`npm run dev:canvas`）
- 画面：1440×900、明るい配色
- 手順：サンプルを観察 → ファイル → 新しいキャンバス → 箱の追加・接続・ラベル → 余白のダブルクリック → 範囲選択して囲む → 整頓 → 図形のメモを書いて図に置く
- 比較対象：Excalidraw、tldraw、draw.io、Miro、Whimsical の一般的な操作

## 重要度順の指摘

### A. 言葉と概念

**A1. 「メモ」が4つの別のものを指している**

| どこで | 実体 |
|---|---|
| ツールバーの「メモ」、余白のダブルクリック | キャンバスに置く独立した文章 |
| 選択パネルの「メモ」欄 | 図形の中に隠れている補足（図には出ない） |
| 「メモを図に置く」 | 上の補足を図の上に表示したもの（「API のメモ」） |
| 箱の右下の「メモ」の目印 | 補足があることの印 |

サンプルでは「今回の方針」（独立した文章）と「Worker のメモ」（図形の補足）がまったく同じ見た目で並ぶ。違いは薄い点線だけで、初見では区別できない。下部の「5 図形 / 2 メモ」の件数も、どちらを数えているのか分からない。

改善案：キャンバスに置く文章は「テキスト」（Excalidraw・tldraw と同じ）、図形の補足だけを「メモ」と呼ぶ。図に置いたメモは、図形との点線をはっきりさせるか、見出しに図形名を強調して「付属している」ことを見せる。

**A2. 選択パネルの見出しが「図形とメモ」で、メモ欄に説明がない**

図形を選ぶと、パネルの見出しは「図形とメモ」になる。その中の「メモ」欄が図に表示されない補足だとは、書いてみるまで分からない。

改善案：見出しは「図形」にする。欄名を「メモ（図には表示されない補足）」にするか、プレースホルダーで説明する。

### B. 見ただけでは用途が分からない部品

**B1. 接続点の○**（ユーザー指摘）

選択すると上下左右に○が出るが、形からは用途が読み取れない。クリックしても、左下のステータスバーに小さく「接続先を選んでください」と出るだけで、画面上はほとんど変化がない。説明はブラウザ標準のツールチップだけで、しばらく止めないと出ない。

改善案：○を外向きの矢印にする（draw.io・Whimsical）。クリックすると、その方向に同じ形の図形をつないで追加する（Miro・Whimsical）。ポインタを乗せたらすぐ「クリック：この方向に図形を追加／ドラッグ：別の図形へ接続」と表示する。

**B2. 選択したときの装飾が多い**

箱を1つ選ぶと、四角いつまみ8個、○4個、「編集」ボタン、右のパネルが同時に出る。どれを使えばよいか迷う。

改善案：「編集」ボタンはダブルクリックと Enter で足りるので外す。接続点はポインタを乗せた辺の近くだけ強調するなど、同時に見える部品を減らす。

**B3. 「整頓」が何をしたか分からない**

2つの箱で試すと、Queue が数px動いただけで、ステータスバーに「図形と線を整えました」と出た。名前からは自動レイアウトを想像するが、実際は線がまっすぐになるよう小さく揃えるだけ。何も変わらないときも同じ表示になる。

改善案：名前を「位置を揃える」などに変える。動いた図形を一瞬強調するか、「3個の図形を揃えました／揃える必要のある図形はありません」と結果を具体的に伝える。

### C. 入力の作法が一般的なツールと違う

**C1. 余白のダブルクリックでフォームが出る**（ユーザー指摘）

「見出し（任意）」と「メモ」の2欄と「追加 ⌘Enter」が出る。その場に書くのではなく、ダイアログに入力している感覚になる。Excalidraw・tldraw では、余白をダブルクリックすると、その場にカーソルが出てすぐ書ける。

改善案：入力欄を1つにして、クリックした位置で直接書けるようにする。1行目を見出しのように太く表示すれば、今の見た目を保てる。

**C2. Esc で入力が消える、確定は ⌘Enter**

Esc は入力の取り消しになっている。Excalidraw では Esc で確定し、多くのツールでは「書いた文字は消えない」が前提になっている。説明欄の Enter は改行で、確定には ⌘Enter が必要。

改善案：Esc は確定にし、取り消しは ⌘Z に任せる。少なくとも、文字が入っているときは Esc で消さない。

**C3. 線のダブルクリックでラベルを書けない**

線をダブルクリックしても線が選ばれるだけで、パネルの「線のラベル」欄にもフォーカスが移らない。draw.io・Excalidraw では、線をダブルクリックするとその場でラベルを書ける。

改善案：線のダブルクリックで、線の中央にラベル入力欄を開く。

### D. 表示が飛ぶ・隠れる

**D1. 余白のダブルクリックで表示位置が動く**

入力欄を画面内に収めるための補正で、図全体が約40px上に動いた。クリックした場所と書き始める場所がずれる。

**D2. パネルの下に要素が隠れる**

囲みを作ると右半分がパネルの下に隠れ、表示位置は変わらない。「メモを図に置く」で置いたメモも、パネルの下に半分隠れる（前回レビュー指摘4が残っている）。

**D3. 図に置いたメモが他の図形や囲みと重なる**

API のメモが右隣の Queue と囲みに重なって置かれた。配置は「親の右72px、重なれば下へ」という単純な規則のままで、#11（新しい図形の配置）の空き場所探しを使っていない。

改善案：D2・D3 とも、置き場所の探索に `placeInFreeSpace` を使い、置いたあとは見える位置まで表示を動かす。

### E. 見た目の不具合

- **E1.** 線を選ぶと、ブラウザ既定のオレンジのフォーカス枠が線の上下に出る（`g.edge-control` の `outline: auto`）。
- **E2.** テキストを ⌘Enter で確定すると、キャンバスに青い枠が出る。#18 の判定が文字入力のキーまで「キーボード操作」と数えているため。Tab や矢印など、移動のキーだけを数えるべき。
- **E3.** ツールバーの図形ボタンを押すと、「箱 B」のツールチップが入力中も出たままになる。
- **E4.** 接続点をドラッグして図形を追加したあとも、ステータスバーに「接続先を選んでください」が残る。
- **E5.** テキストの縦線と選択枠が文字よりかなり大きい（短い1行でも高さ約100px）。

### F. 最初の一歩

- **F1.** 空のキャンバスのアイコンは箱なのに、主ボタンは「メモを追加」。構成図のツールとしては「図形を追加」が自然。
- **F2.** 「新しいキャンバス」が、ブラウザに保存している今の図を置き換えることを告げない（前回レビュー指摘2が残っている）。
- **F3.** ヘルプはショートカットの一覧表だけで、「まず何をすればよいか」が分からない。

## 進め方の提案

関連するものをまとめて、stack の上に積む。

1. **言葉と入力の整理**：A1・A2・C1（「テキスト」と「メモ」を分ける、ダブルクリックでその場に書く）
2. **接続点の再設計**：B1・B2・E4
3. **入力の作法**：C2・C3
4. **隠れる・重なる**：D1・D2・D3
5. **小さな見た目の不具合**：E1・E2・E3・E5（E2 は #18 の修正）
6. **整頓と最初の一歩**：B3・F1・F2・F3

1 と 2 がユーザーの指摘そのもので、効果も大きい。5 は手間が小さいので、どこで入れてもよい。
