# SimpleERの整頓・配線とELK / libavoidの実測比較

2026-10-02（JST）。対象ブランチ: `feature/relational-model-layout`。

## 結論

**現行の配置を維持し、libavoidの配線を次の候補として検証する。現段階では本体を置き換えない。** 今の3テーブルは現行でも十分に単純な線になっている。一方、同じidへの多数の参照ではlibavoidが明確に改善した。ただし、循環図では別の関係の線が重なる問題が残った。

ELKは線を直線にするためにテーブルの高さをずらす。総曲がり数は減るが、ユーザーが好んだ「上端が揃う」見た目は失われる。この条件を調整していない今回のELK設定を、そのまま標準の整頓にすることは勧めない。

- [比較画面（単独HTML）](../experiments/routing-comparison/output/comparison.html): 図・比較対象を切り替え、上下に同じ倍率で表示。大きな図は100%表示でスクロールできる。
- [生データ・座標・経路・設定・時間](../experiments/routing-comparison/output/results.json)
- [再実行の手順](../experiments/routing-comparison/README.md)

本体のソース・保存データ・依存パッケージは今回変更していない。外部エンジンは比較実験のディレクトリにのみインストールし、描画結果をローカルの比較ページへ出力した。

## 比較条件

| 比較対象 | テーブル配置 | 線 |
| --- | --- | --- |
| 現在 | SimpleERの整頓 | 現在の経路計算 |
| libavoid | 現在と同じ座標 | libavoidで再計算 |
| ELK | ELK Layered | ELKの直交配線 |
| ELK＋libavoid | ELKと同じ座標 | libavoidで再計算 |

テーブルの幅・高さ・カラム中心位置・左右の接続面・角丸・鳥の足は共通。鳥の足は本体のReactコンポーネントで描画した。最低28pxの水平な端点区間を確保するため、libavoidにチェックポイント、ELKに28px外側の固定ポートを設定している。同じ端点の線の共有を許す。テーブルや線の形状は生成後に手直ししていない。

3テーブルのケースは、比較開始時にページの `inspect_diagram` で読み取った図を `current-input.json` に固定したもの。動詞ラベルのケースは `examples/live-streams.json` を使用し、`posted_at` の型などが現在の図とは異なる。各ケース内では全エンジンに同じ定義を渡している。

ラベルは全方式で現在の `relationshipLabels` を使用。ELK固有のラベル配置は今回比較していない。現在の整頓はラベルの幅を列間隔に反映するが、ELKへラベル寸法は渡していない。ラベル付きケースは完全な機能比較ではなく、現在の描画へ組み込んだ場合の観察である。

## 実測結果

表は **曲がり数 / 交差数 / 共通端点のない線の重なりの組数**。小さい値だけで美しさを決めず、共有が許される端点と、それ以外の重なりを区別する。

| 図 | 現在 | libavoid | ELK | ELK＋libavoid |
| --- | ---: | ---: | ---: | ---: |
| 今の3テーブル | 6 / 0 / 0 | 6 / 0 / 0 | 4 / 0 / 0 | 4 / 0 / 0 |
| 動詞ラベルあり | 6 / 0 / 0 | 6 / 0 / 0 | 4 / 0 / 0 | 4 / 0 / 0 |
| 分岐する11テーブル | 20 / 0 / 0 | 20 / 0 / 0 | 10 / 0 / 0 | 10 / 0 / 0 |
| 同じidに8本集中 | 20 / 20 / 0 | 16 / 0 / 0 | 14 / 0 / 0 | 14 / 0 / 0 |
| 循環・自己参照 | 10 / 5 / 0 | 10 / 0 / 3 | 12 / 0 / 0 | 8 / 1 / 0 |
| 複合外部キー | 6 / 0 / 0 | 6 / 0 / 0 | 6 / 0 / 0 | 6 / 0 / 0 |

6ケース×4方式、追加・移動の3段階×2方式の計30結果で、テーブル貫通、テーブルの重なり、接続点や向きの不一致、28px未満の端点区間、斜め線、ラベルとテーブル／ラベル同士の重なりはいずれも0。循環図の線同士の重なりは上表のとおり残る。

同じ入力の反復、およびテーブル・辺の入力配列を逆順にした場合、6ケース×4方式すべてで配置と経路が一致した（比較精度0.001px）。将来のバージョン・別環境・任意のグラフまで保証するものではない。

### 目視で確認した違い

- **今の3テーブル:** 現行とlibavoidの線の合計長はともに862px。libavoidはUsers.idからの共有部分を長く取る。現行の早い位置での分岐も素直で、置き換えによる明確な改善とは感じなかった。ELKはUsers / LiveStreams / Commentsの上端をそれぞれy=156 / 118 / 80へずらす。直線が増える一方、Comments.user_idへの長い線は下へ迂回して戻る。
- **11テーブル:** ELKは曲がりを20から10へ減らすが、図の高さは872から1106pxへ増えた。現行は上端と列が揃い、表の集まりを追いやすい。libavoidは現行の座標・曲がり数・長さを保ち、共有する幹の位置が変わる。
- **同じidに8本集中:** 現行には折り返しと縦線の束が現れる。libavoidは共通の幹から各テーブルへ分岐し、許容された共有によってすっきりする。交差20→0、曲がり20→16。今回最もはっきりした改善。
- **循環:** libavoidの交差0を、そのまま改善とは評価できない。異なるカラム間の関係が3組重なり、一本の線に見える。ELK単独はこれを避けるが、線の長さが1836→3108px、図の幅が608→970pxへ増える。ELK配置にlibavoidを組み合わせても交差1が残り、組み合わせれば常に良いわけではない。
- **複合キー:** 全方式で2カラムの対応と自己参照を描けた。ELKは独立したcategoriesの置き方が変わり、図の高さを534→410pxに縮めた。

### テーブル追加・移動

UsersとCommentsを固定し、途中に背の高いArchiveを追加、その後Archiveを580px下へ移動した。libavoidは同じRouterへ図形追加・移動を通知し、差分更新した。

| 操作 | 現在: 曲がり / 線長 | libavoid: 曲がり / 線長 |
| --- | ---: | ---: |
| 追加前 | 2 / 688px | 2 / 688px |
| 途中にテーブル追加 | 4 / 1158px | 4 / 1126px |
| 障害物を下へ移動 | 2 / 688px | 2 / 688px |

どちらも既存テーブルを動かさずに迂回し、通路が空くと元の短い経路へ戻った。接続は1本のため、多数の無関係な線が揺れないかは、この実験からは判断できない。新しいFKの追加や、接続面が入れ替わるテーブル移動は未検証。

### 端点の余白と線の間隔の干渉

同じ設定から28pxのチェックポイントだけを外す補助実験も行った。循環図では共通端点のない線の重なりはなくなるが、交差5、28px未満の端点区間7となった。複合キーでも短い端点区間が2つ生じた。結果は生データの `metadata.unguardedSensitivity` に記録している。

**推論:** 今回の固定チェックポイントが、同じ側へ接続する線をずらす自由度を減らしている。これは採用アダプターの制約の与え方を含む結果であり、libavoid全般が循環を処理できないという結論ではない。鳥の足の余白を守りつつ、中間の幹を別々の場所へ配置できるようにすることが、次の検証課題。

## 再現環境・設定

- 実行日: 2026-10-02 JST。Apple M1 Pro / macOS arm64 / Node.js v24.19.0。
- elkjs **0.12.0**、libavoid-js **0.5.0-beta.5**。比較用の `package-lock.json` に固定。
- ベースコミット: `07edb963ec87b9a01a36ebea105255aace5cc588`。**未コミットの現行実装が比較対象**であり、このコミットだけでは再現しない。本体ソース6ファイルのSHA-256は `results.json` の `metadata.sourceSha256` に記録。
- libavoid: OrthogonalRouting、shapeBufferDistance=8、idealNudgingDistance=12、segmentPenalty=180、crossingPenalty=160。共通端点の共有区間および図形に直接接続した区間をずらすオプションはfalse。固定カラムピンはexclusive=false。両端から28pxのチェックポイントを置く。
- ELK: Layered / RIGHT / ORTHOGONAL / seed=1 / FIXED_POS。縦余白96px、辺同士12px、辺とノード18px。ポートを28px外に出すため、列間の指定を64pxにして基本のテーブル間隔を現行と同じ120pxにした。初期の指定120pxでは実際の表間隔が176pxになったため修正し、最終結果を再生成した。接続面は現行の整頓を基準に固定し、ELK固有の接続面選択は使っていない。
- その他の設定は各ライブラリの既定値。設定全体は `engines.mjs` と生データを参照。

時間は初回の処理を除き5回測った中央値。現行は配置＋配線、libavoidは配線のみ。ELKは接続面を決めるための現行整頓とELK配置＋配線を含む。ELK＋libavoid欄はELK配置を再利用するためlibavoid部分だけ。**処理範囲が違うため、この数値で速度の優劣は決めない。**

| 処理範囲 | 3テーブル | 11テーブル |
| --- | ---: | ---: |
| 現行の配置＋配線 | 0.508ms | 2.820ms |
| libavoidの配線 | 1.141ms | 2.581ms |
| ELKアダプター全体 | 8.467ms | 11.021ms |
| ELK配置後のlibavoid部分 | 0.512ms | 1.513ms |

別途計測したWASM読み込み・初期化は約86ms（1回）。ブラウザの描画、配信サイズ、操作中の遅延、モバイル実行速度は測っていない。

## 計測と検証の範囲

曲がりは重複点・一直線上の中間点を除いて数え、長さは中心線のマンハッタン距離。交差は直交する線分の内部同士の交点を、線の組ごと・位置ごとに数える。接触点、曲がり角での接触、重なる線は交差に含めない。共有長は線の組ごとの合計であり、画面上のインクの総延長ではない。共通端点のない重なりを別項目で集計した。

ラベルと他の線の交差、端点の鳥の足同士の衝突、1px未満の近接は数値集計の対象外。角丸前の中心線を計測しているため、読みやすさは画面でも確認した。

比較ページを1440×900、768×1024、375×812で確認。3テーブル・11テーブル・集中・循環・複合キー・追加後・動詞ラベルを目視し、対象の切り替え、100%表示、共通の関係の強調も確認した。最初の表示では縦長の図を一度に見られなかったため、全体表示を高さ560pxにも収めるよう修正。狭い画面では全体表示は形を見る用途で、文字は100%表示が必要。

自動確認は30結果の形状・端点チェック、24組の反復・入力逆順チェック、交差と共有区間の集計に関する2テスト。本体ソースを変更していないため、本体のビルドや全回帰テストは今回再実行していない。

実験の最大規模は11テーブル。大規模図、長時間編集、メモリ、手動経路・undo・保存との統合、WASMのブラウザ配信、失敗時のフォールバックは未検証。実用採用の判断はこれらと循環図の改善を確認してから行う。
