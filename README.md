# SimpleER

Web版の公開先は https://nibuno.github.io/simple-er/ です。ブラウザに保存した図は、別端末やローカル版には同期されません。「ファイルに保存」でJSONを書き出し、移動先で「ファイルを開く」を使ってください。

同じ雰囲気で構成図とメモを扱う姉妹ツール [SimpleCanvas](canvas/README.md) を追加しています。`start-canvas.command` で別途起動できます（http://127.0.0.1:8766/）。SimpleERとは画面・自動保存領域を分けています。

線や配置の調整に手間をかけず、ER図を書くためのローカルツール。画面上の名称は「SimpleER」です。

`start.command` をダブルクリックすると、ローカルサーバーとブラウザが開きます。Python 3 が必要です。このMacでは利用できることを確認しています。

表示先は常に http://127.0.0.1:8765/ です。起動用ウィンドウを閉じるか Ctrl+C で終了します。再起動するにはもう一度 `start.command` を開いてください。

## 操作

- 画面構成：左にテーブル・リレーションの一覧（絞り込み可）、中央にキャンバス、テーブル選択時は右に詳細パネル。一覧の項目を選ぶとキャンバス上の位置へ移動します。
- テーブルの選択：見出しをクリック。関連する線とカラムを強調し、詳細パネルで物理名・論理名の変更、カラムとキーの確認、DDL（PostgreSQL形式）のプレビューとコピーができます。「詳細エディタで開く」でテーブル編集画面へ。Escで選択を解除。
- ショートカット：T でテーブルを追加、Delete（⌫）で選択中の外部キー・テーブルを削除、⌘Z／⇧⌘Z で元に戻す・やり直す。
- テーブルを追加：物理名、任意の論理名（日本語名）、カラム、型を入力。カラム行の「主キー」「一意」で設定し、「参照先」から外部キーを登録。複合キーやインデックスは同じ画面の一覧で編集。
- 表示名：図の表示を物理名／論理名に切り替え。論理名が空欄の場合は物理名を表示。自動接続は物理名から判定。
- 各テーブルの「編集」：名前の変更、カラムの追加・削除・並べ替え。残ったカラムの接続は保持されます。
- 拡大・縮小：キャンバス上でトラックパッドをピンチすると、ポインター位置を中心に25〜400%でズーム。右下の拡大率表示も連動します。
- キャンバスの移動：Macのトラックパッドで2本指スクロールすると上下左右に移動。空白部分のドラッグでも移動できます。
- テーブルの見出しをドラッグ：自動の線は接続面と経路を追従させます。ほかのテーブルは移動しません。
- 外部キーの登録：カラム行にポインターを乗せると左右の端に点が出ます。点から別のテーブルのカラムへドラッグすると接続します（どちらが参照先かは主キー・一意制約から判定）。カラム行のクリックはテーブルの選択だけで、接続は始まりません。キーボードではカラム行で Enter を2回（接続元・接続先）押して接続でき、Escで取り消せます。同じテーブル内の参照（自己参照）や複合外部キーは編集画面の「参照先」で設定します。
- テーブル名・カラム名をダブルクリック：現在の表示名（物理名／論理名）を直接編集。Enterで確定、Escでキャンセル。カラム行のF2でも開始できます。
- 線を選択：「外部キーを編集」で参照設定へ移動。「外部キーを削除」は複合外部キーの線すべてを削除。
- 線を選択して「経路を調整」：調整可能な縦区間に小さなつまみを表示。ドラッグ・左右キーで動かせます。「線を自動に戻す」はその外部キーの全線を自動経路に戻します。
- 自動で接続：`user_id → users.id` のような名前から候補を表示し、選択した候補をまとめて接続。テーブルは移動しません。
- 整頓：参照先を左、参照元を右へ配置。一本道は上端を揃え、分岐は接続先に合わせて上下順を調整します。循環は同じ列、独立したテーブル群は空いた領域へ配置。実寸と関係ラベルの幅で間隔を取り、現在位置・画面幅に依存しません。線はテーブルを避け、短い段差と不要な曲がりを抑えます。同じカラムの接続点と水平部分は共有できます。「元に戻す」で手動経路も復元できます。
- 関係の表示：1／多を線の両端に表示します。線の「外部キーを編集」から関係ラベルと最小件数を設定できます。1対1は参照元の主キー・一意制約から判定。通常のインデックスは判定に使いません。旧データの最小件数は推測せず、未指定の間は最大件数だけを表示します。
- 元に戻す・やり直す：編集、接続、削除、読み込みにも対応（履歴は起動中のみ）。

## 保存

図は操作確定時に、このURLを開いたブラウザに自動保存されます。同じブラウザ・同じURLで再開してください。ブラウザのデータ削除やプライベートブラウジングでは保持されない場合があります。

「ファイルに保存」でJSONのバックアップを作り、「ファイルを開く」で復元できます。テーブル、カラム、接続、手動で調整した線の位置を含みます。読み込み失敗時には現在の図を保持します。読み込み成功後も「元に戻す」で直前の図に戻れます。

保存・編集データの外部送信は行いません。Web版とローカル版のデータは別です。

## 自動接続の範囲

`*_id` とテーブル名（同名または基本的な単数・複数形）を照合し、参照先の主キーが1つで型が一致する場合に候補を出します。接続済みのカラムは対象外です。曖昧な候補・複合主キー・型の不一致は見送り、理由を表示します。データベースの制約を読み取る機能ではありません。

現在の上限は40テーブル、各60カラム、200接続です。大きな図での速度は今後の改善対象です。自己参照・複合外部キーに対応しています。交差を減らす処理はありますが、どの図でも交差ゼロや最短経路になる保証はありません。

## 今後

- Mermaid形式への出力（関係情報の出力。手動配置や線の経路をそのまま再現できるものではありません）
- SVG・PNGでの画像出力

保存形式は `format: "er-sketch"`, `version: 2`。定義を `schema`、座標・経路を `presentation` に分離しています。テーブルとカラムの識別子を名前から分離しているため、編集時に関係を保ち、今後の出力機能からも同じ図のデータを利用できます。

## 開発時の確認

React + TypeScript（strict）+ Viteで実装しています。Node.js 22.18以降を使用してください。

```sh
npm ci
npm run dev       # 開発用: http://127.0.0.1:5173/
npm run build     # 型チェックと dist/ の生成
npm test          # 保存・接続・整頓・履歴・Reactの操作を検証
npm run format    # ソースコードを整形
```

通常利用は従来どおり `start.command` で起動できます。生成済みの `dist/` を配信するため、通常起動にnpmは不要です。ソース変更後は `npm run build` で更新します。開発用のURLは保存領域が異なるため、従来の図を確認する場合はビルド後に http://127.0.0.1:8765/ を再読み込みしてください。

- `src/App.tsx`：図の状態・履歴・保存・ツールバー
- `src/DiagramCanvas.tsx`：SVG描画、ドラッグ、拡大縮小
- `src/Dialogs.tsx`：テーブル編集と自動接続の候補
- `src/Panels.tsx`：テーブル一覧と詳細パネル
- `src/ddl.ts`：DDLプレビューの生成
- `src/types.ts`：テーブル・カラム・接続の型
- `src/model.ts`：保存形式の検証・編集・接続推測
- `src/geometry.ts` / `src/layout.ts`：線の経路計算・整頓
- `src/history.ts`：元に戻す・やり直す

保存キーは旧版と共通です。旧版のJSON（version 1）は読み込めますが、保存後のversion 2を旧版アプリでは読み込めません。旧データから移行する際、自動保存の元データは `.v1-backup` キーへ退避します。`dist/` は生成物なので直接編集しません。

## このブランチの試用

`examples/composite-keys.json` を「ファイルを開く」で読み込むと、複合主キー・複合外部キー・一意制約・複数カラムのインデックス・自己参照を試せます。

- カラム行の「主キー」は一つの主キーの構成カラム、「一意」はそのカラムだけの一意制約を設定します。複数の「一意」チェックは別々の制約です。
- 下部の「キー・インデックス」は一つの定義を一行で表示。「＋ 追加」や「編集」で対象カラムを選び、←／→で順序を変更できます。複合一意制約はここで設定します。
- カラム行の「＋ 参照先」から外部キーを追加し、既存の `users.id ↗` などを押すと編集できます。図の線の「外部キーを編集」も同じ編集欄を開きます。一つのカラムが複数の外部キーに含まれる場合は、すべての参照先を表示します。
- 外部キーは左右に参照元と参照先を並べて設定。参照先には主キー・一意制約が候補として表示されます。複合キーは複数行で対応を指定します。参照先候補が一つの場合は自動選択します。
- 定義の「編集を取り消す」はその定義だけを戻します。「完了」で一覧へ戻り、テーブルの「変更を反映」で図に保存します。テーブルの「キャンセル」はその画面で行った編集全体を取り消します。
- 参照先には同じ順序・個数の主キーまたは一意制約が必要です。通常のインデックスは参照先にできません。
- 参照先未設定の外部キーは保持でき、画面に「要確認」と表示します。未設定の外部キーからは線を描きません。
- 旧データの線は、単一主キーとFK表示から方向を一意に判断できるものだけ移行します。曖昧な線は `unresolvedEdges` に元の記録を残し、図の上部で確認できます。ここに表示するカラム番号は移行前の番号です。
- 参照元カラムの削除時は、そのカラムを含む制約全体を削除します。参照先カラム・テーブルの削除や主キー・一意制約の変更時は、影響する外部キーを参照先未設定として残します。編集画面で影響を確認でき、図の「要確認」から参照先を設定できます。
- データベースへのDDL出力・制約の型互換性の検査は今回の範囲外です。

`examples/live-streams.json` は Users・LiveStreams・Comments の関係ラベルと鳥の足記法、`examples/layout-branches.json` は11テーブルの分岐と長い参照を確認する例です。

設計と検証の記録は `IMPLEMENTATION.md` を参照してください。既存エンジンとELK・libavoidの比較結果は [配線の比較調査](docs/routing-comparison-research.md)、再実行方法は [比較実験](experiments/routing-comparison/README.md) にまとめています。

GitHub Pagesでの試用公開と `nibuno.dev` のサブドメインへの移行は [Web公開方針](docs/web-publishing-plan.md) にまとめています。

## Web版の更新

`npm run build:pages` でSimpleERのみを `dist-pages/` に生成します。通常のローカル配信用 `dist/` とSimpleCanvasには影響しません。

GitHubのデフォルトブランチへ変更をpushした後、Actionsの「Publish SimpleER」から「Run workflow」を実行します。テストと型チェックが成功するとGitHub Pagesへ配信されます。PagesのSourceは「GitHub Actions」を指定します。pushだけでは公開内容は変わりません。

## モデリングの確認と保存競合

「要確認」は参照先未設定の外部キーと旧データの線をまとめて表示します。外部キーの「編集」から参照先を設定できます。旧データの線は、必要な参照関係を設定してから「破棄」できます。表示する列番号は移行前の位置です。破棄は保存されますが、再読み込みまでは「元に戻す」で復元できます。

同じER図を別タブで変更すると、自動保存を停止します。この画面の編集は「ファイルに保存」で残せます。「保存されている図を読み込む」で別タブの保存内容を取り込み、自動保存を再開します。読み込み時に編集履歴をリセットするため、残したい編集は先にファイルへ保存してください。

内部処理は旧形式の準備・制約検証・描画用の線生成・キー表示更新に分けています。ERとCanvasは別エディタのまま、履歴処理と別タブ変更の検知を `shared/` で共通化しています。保存形式は従来のv2です。

### 定義と表示の型

実行時の正本は `DiagramDocument` です。`schema` はテーブル・名前付きの `Column`・キー・外部キー、`presentation` はテーブルIDごとの座標と外部キーID＋参照元カラムIDごとの経路を持ちます。旧データの未確定の線は `unresolvedEdges` として別に保持します。Undo・Redo、自動保存、ファイル出力はこの文書を扱います。

描画・レイアウト・編集フォームは `projectDocument` が生成する `Diagram` を使います。行番号、PK/FK表示、描画用の線は派生データで、正本には保存しません。編集結果は `documentFromDiagram` で正本へ戻します。Columnのタプル形式はv1読み込み時の `migrateLegacyDiagram` で変換します。

保存形式は引き続きv2です。不正な表示情報（重複・存在しない参照・座標や経路の型違い）は読み込み時にエラーにし、現在の図を保持します。
